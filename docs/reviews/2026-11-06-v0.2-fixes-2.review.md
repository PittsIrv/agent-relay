## 1. Correctness risks

1. **Failed `take` from review restores a PR that can no longer complete the task.** `hold` increments the epoch, but `unhold` restores the old `pr_epoch` without reconciling it with the new epoch. The strengthened `mark_done` then rejects that PR even if it merges. Fix 1.7 is incomplete.
   **Evidence:** `task["epoch"] += 1`; `held_from` includes `"pr_epoch"` but not `"epoch"`; `mark_done` rejects `task.get("pr_epoch") != task["epoch"]`.

2. **Failed `take` can subsequently close the very PR it restored.** The rollback leaves the `held` event’s retirement instruction intact. A later flush by that worker will execute it, despite the PR having been restored as current. Background processing could also execute retirement before rollback finishes.
   **Evidence:** `event(task, "held", ... retired_pr=old)`; `unhold` restores fields and appends `"released"` without invalidating that event; `flush` executes `self._retire(ev["retired_pr"], task)`.

3. **Failed `take` of an expired running task creates an inconsistent running task with no lease.** Such tasks are explicitly eligible for `hold`; rollback restores `"running"` but unconditionally clears the lease. At minimum, another `hold` will attempt to subscript `None`.
   **Evidence:** `expired = task["status"] == "running" and task["lease"]["until"] < current`; `held_from` saves `"status"` but not `"lease"`; `unhold` sets `task["lease"] = None`.

4. **Closing a rejected stale PR is not crash- or outage-safe.** Its number is not durably recorded before `_retire` performs GitHub calls. A crash or failed close after rejection can leave an open superseded PR with no shown recovery path. Adoption of the current checkpoint’s PR does not recover this older attempt. Thus fixes 1.1 and 1.6 do not fully establish the claimed supersession cleanup.
   **Evidence:** `if not tasks.attach_pr(...): self._retire(number, task)`; the rejection path in `attach_pr` simply returns `False`; recovery searches only `self.gh.find_pr(cp["branch"])`.

5. **PR attachment is not idempotent: a duplicate completion can close the valid current PR.** If the same PR has already been attached at the same epoch, `attach_pr` returns the same failure result as a genuinely stale attempt. `_open_pr` then retires it. The normal-path reachability depends on serialization outside the supplied excerpt, but the failure behavior itself is explicit.
   **Evidence:** attachment rejects whenever `task.get("pr") is not None`; every rejected attachment invokes `self._retire(number, task)`.

6. **Normal shutdown can abandon a live GitHub job.** A sequence of API calls can exceed 120 seconds even if individual calls have timeouts. After the timed join, the worker announces offline without checking whether the thread stopped. In a persistent Python process the thread can continue; at interpreter exit it can be terminated between remote side effects and state recording.
   **Evidence:** `threading.Thread(..., daemon=True)` and `self._syncing.join(timeout=120)` immediately followed by `self.announce("offline")`.

## 2. Hidden assumptions

1. **Fix 1.2 depends on local thread safety that this package does not establish.** Moving the two visible calls off the heartbeat loop removes their direct blocking, but the background thread shares the worker’s `Conversation` and store. Remote compare-and-swap does not establish safe concurrent use of local Git scratch state, caches, or configuration.
   **Evidence:** `Conversation(..., self.store, ...)`, `self.in_background(self.talk.flush, task)`, and `self.in_background(self.sync)` all reuse existing objects.

2. **PR adoption assumes a head branch uniquely identifies the intended PR, regardless of its status or base.** The lookup accepts the first result across all states. It can select a closed, unmerged PR or an otherwise unsuitable PR sharing that head; no identity or compatibility validation is shown.
   **Evidence:** `found = self.api("GET", ..., head=f"{owner}:{branch}", state="all")`; `return found[0] if found else None`.

3. **Issue adoption assumes the orphan remains discoverable in the bounded labelled-issue listing.** Removing its label, closing it if the listing is open-only as described, or placing it beyond the cap defeats adoption. Fix 1.6 provides bounded recovery, not an unconditional “never duplicate” guarantee.

## 3. Design decisions I would challenge

1. **Safety-relevant retirement should not be a narration side effect.** I would weigh a durable retirement queue, reconciled independently of comment delivery, or removing automatic `Closes #N` behavior until retirement is reliable.
   **Evidence:** `_retire` says its purpose is to prevent a superseded PR’s `` `Closes #N` `` from closing the live issue, but it runs while posting pending events.

2. **A timed join on a daemon thread is not a sufficient worker lifecycle contract.** I would weigh a managed background worker with explicit shutdown, bounded jobs, observed failures, and documented ownership of shared resources.
   **Evidence:** the lifecycle mechanism is `daemon=True` plus `join(timeout=120)`; the helper’s contract only says the next periodic sync “catches up.”

3. **The non-draft fallback remains a policy change worth making explicit before PR creation.** “Still unmerged” does not make a ready-for-review PR equivalent to a draft; readiness-sensitive automation and collaborator expectations can differ. I would weigh an explicit repository setting.
   **Evidence:** `self.api("POST", self.repo("/pulls"), {**request, "draft": False})`; adjudication 3.3 rejects opt-in because otherwise some repositories would have no PR by default.
