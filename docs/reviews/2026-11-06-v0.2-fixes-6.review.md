## 1. Correctness risks

1. **Hand-back can still attribute an old checkpoint’s check result to new work when the old PR has not attached.** Start with a reviewed checkpoint carrying `verification={"result": "passed"}` but no PR, take it, change the files, then hand it back with `--review`. Retirement is skipped, `handoff()` supplies no new verification, and the new review event records the old “passed” result.  
   **Evidence:** `retired = retire_pr(task) if status and task.get("pr") and task.get("pr_epoch") != epoch else None`; `handoff()` calls `tasks.update(... checkpoint=cp, status=status, ...)` without `verification`; `update()` records `check=check.get("result")`.

2. **Epoch rollback reuses human lease identities, allowing stale operations to match a later hold.** For the same worker, `hold → unhold → hold` produces the same held epoch twice. Replaying the first hold’s `unhold()` or `update()` can therefore release or modify the second hold. Whether production callers can encounter that replay depends on concurrency and recovery restrictions not established here.  
   **Evidence:** `task["epoch"] = previous.get("epoch", task["epoch"])`; subsequent `hold()` executes `task["epoch"] += 1`; `unhold()` authenticates using only worker, epoch and held status.

3. **A capped issue thread can prevent superseded PRs from being closed even while the responsible clone continues running.** `_flush()` reads the entire issue thread before processing retirement events. Once that read raises at the cap, it never reaches `_retire()`, leaving an obsolete PR available to merge and close the live issue.  
   **Evidence:** `remote = "\n".join(... self.gh.issue_comments(task["issue"]))` precedes `if ev.get("retired_pr"): self._retire(...)`; `issue_comments()` uses `complete=True`; `_retire()` explicitly says closure prevents an obsolete PR’s ``Closes #N`` from closing the live issue.

4. **Issue adoption still permits duplicates if an ambiguously created issue is closed or loses its label before recovery.** Completeness now protects against pagination truncation, but only within the filtered search.  
   **Evidence:** `labeled_issues()` searches with `labels=label, state="open"`; `_flush()` then executes `number = existing or self.gh.create_issue(...)`.

## 2. Hidden assumptions

1. **Rollback safety assumes no operation from the discarded hold can remain in flight or be retried.** That assumption is stronger than saying the earlier review attempt had no lease, and it is not enforced by the supplied workflow.  
   **Evidence:** The rollback justification is “Nothing held a lease at the earlier epoch and the hold published nothing”; `Store.change()` locks individual mutations, not the complete `take()` or `handoff()` workflow.

2. **Issue deduplication assumes ownership markers, labels and open status survive an ambiguous creation.** The recovery search cannot find an otherwise valid owned issue outside those conditions.  
   **Evidence:** Adoption tests `owned in (i.get("body") or "")` over `self.gh.labeled_issues(complete=True)`, whose query uses `state="open"`.

3. **Automatic PR recovery depends on the originating clone returning, not merely another worker being available.** This is documented, but it is a material operational dependency.  
   **Evidence:** `_flush()` selects events with `ev.get("worker") == self.worker`; architecture says, “If it never runs again, a superseded PR may stay open; close it by hand.”

## 3. Design decisions to challenge

1. **I would separate monotonic fencing identity from PR publication identity instead of restoring epochs.** A stable publication-attempt identifier can preserve the old review’s pending PR without reusing a human lease token.  
   **Evidence:** The adjudication explicitly chooses “restoring the held attempt’s epoch on rollback rather than a second counter”; `unhold()` implements that decrement.

2. **I would invalidate verification according to checkpoint identity, not PR presence.** Preserve a result only when it is demonstrably for the checkpoint being published; otherwise clear it or record “not checked.”  
   **Evidence:** `retire_pr()` removes `"verification"`, but `update()` invokes it only when `task.get("pr")` is truthy.

3. **I would process durable retirement work independently of conversation-comment deduplication.** At minimum, attempt required PR closures before scanning the task’s comment thread; a repository-visible retirement queue would additionally remove clone-affinity dependence.  
   **Evidence:** `_flush()` performs the capped comment scan before retirement, and retirement events are filtered by their originating worker.

## 4. What a skeptical PI or senior engineer would ask first

1. **Can an end-to-end handoff test prove that changing a checkpoint without an attached PR cannot inherit a passing check?** The added test covers only the attached-PR path and injects verification directly into the state API.  
   **Evidence:** `test_hand_back_keeps_its_own_check_result` calls `tasks.update(... status="review", verification={"result": "passed"})`; production `handoff()` does not supply that argument.

2. **What rejects an old hold token after rollback and reacquisition by the same worker?** A regression test should explicitly attempt both an old `update()` and an old `unhold()`.  
   **Evidence:** `hold()` increments the restored epoch, while both mutation functions accept matching worker/epoch credentials.

3. **What happens when a new attempt retires a PR whose task issue has reached the comment cap?** The required observable result is closure of the obsolete PR, even if its explanatory comments must defer.  
   **Evidence:** The new truncation test only asserts that `gh.issue_comments()` raises; it does not exercise retirement through `_flush()`.

4. **Where is the delayed-GitHub, two-worker execution trace?** The supplied sequential tests exercise selected interleavings but do not establish the full workflow’s concurrency behavior.  
   **Evidence:** The adjudication lists “Slow-GitHub two-worker trace → **open**”; the new mid-take test directly sequences `hold()`, `_open_pr()` and `unhold()`.

## 5. Documentation gaps

1. **The package does not establish whether concurrent interactive commands in one clone are supported or prohibited.** That boundary is necessary to assess rollback’s fencing assumptions.  
   **Evidence:** The supplied locking documentation says only, “Threads of one process (heartbeat and GitHub sync) take turns per clone”; `take()` and `handoff()` have no shown whole-operation lock.

2. **The package does not specify the validity contract linking verification to a checkpoint.** It is unclear when a result must be cleared, preserved or regenerated during interactive hand-back.  
   **Evidence:** `update()` accepts `checkpoint` and `verification` independently, while `handoff()` publishes a checkpoint without supplying verification.

3. **The runbook does not explain recovery when page-cap deferral blocks PR retirement indefinitely.** Closing superseded PRs manually is documented for a clone that never returns, not for a live clone permanently blocked by a large thread.  
   **Evidence:** Architecture says duplicate checks “defer instead,” and separately says, “If it never runs again, a superseded PR may stay open; close it by hand.”

4. **The package does not show how the new pagination exceptions are contained by normal worker execution.** I cannot verify the claim that every affected operation defers rather than aborting a broader synchronization pass.  
   **Evidence:** `pages()` raises `RelayError`, while the supplied `_flush()` has no surrounding handler; the outer `flush()` and `flush_all()` implementations are absent.

## 6. What is done well

1. **The added publication tests cover both sides of failed-take rollback.**  
   **Evidence:** `test_pr_published_during_a_failed_take_still_completes_the_task` and `test_pr_publication_resumes_after_a_failed_take`.

2. **Retiring an attached old PR before assigning new verification fixes the reported overwrite for that path.**  
   **Evidence:** In `update()`, `retire_pr(task)` now precedes `task["verification"] = verification`.

3. **Merged-while-held completion explicitly clears the human lease and hold metadata.**  
   **Evidence:** `mark_done()` sets `task["lease"] = None` and executes `task.pop("held_from", None)`.

The fixes address the reported interleavings, but they are not complete: a legitimate hand-back can still label new work with an old passing check, rollback reuses fencing credentials, and pagination deferral can obstruct safety-relevant PR closure. Documented alpha limitations can cover bounded synchronization and manual recovery; they should not substitute for correct verification attribution or a defensible lease-identity invariant. Fix those paths and add workflow-level regression tests before release.
